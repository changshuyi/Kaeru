### 4b. 沒讀到金額（`49-quick-add-no-amount.png`）

**Bug：金額讀不到時畫面顯示「從照片讀到的含稅金額 ¥0」。** 這句話在騙人 — 使用者會以為 OCR 判斷金額是 0 元，而不是沒讀到。

根因是把「沒讀到」編碼成 `0`。0 是一個合法金額，存進 state 之後就分不出是讀到 0 還是沒讀到。**OCR 沒有結果時一律回傳 `null`，不要回傳 0**；後備規則本身可以留，只是它的「無結果」也要是 `null`。顯示層再決定 `null` 長什麼樣。

`null` 時的畫面（照店名／日期那套做，但更強硬 — 金額是必填）：

- 照片標籤從 `讀到金額了`（sage）換成 **`沒讀到金額`（clay 填色）**
- `#F4F2EF` 的金額摘要區塊**整塊不出現**，換成一般的底線式輸入欄：段落標籤「含稅金額」+ placeholder「照收據上的合計填」20/600 `sub` 色 + 右側 `¥` 提示，底線 `1px solid #494640`（等著被填）
- 下方標籤：`要填才能存`（clay 填色）+ `稅率也要選`（線框）
- 說明 11.5px `sub`：「照片有點模糊，金額沒讀出來。收據最下面那行『合計』的數字填進來就好。」— 講清楚去哪裡找那個數字
- **主 CTA 停用**：`#F4F2EF` 底 + `1px solid #E1DCD5` + `sub` 文字「填了金額才能存」。次要動作換成「重拍一張」
- 稅率同樣沒讀到時不要預設 10%，讓使用者選

店名和日期可以待補，金額不行 — 沒有金額的收據在清單上等於一張空卡，也算不出達標與否。
