# 給 Claude Code 的開工指令

把下面整段貼給 Claude Code。

---

我要把一個已經有 React 原型的 App 換上新的視覺設計。設計稿與規格都在這個資料夾裡。

**先讀這三個檔案，再動手：**

1. `README.md`，完整設計規格（色票、字級、每個畫面的版面、RWD 規則）
2. `Kaeru 產品畫面.dc.html`，設計稿，用瀏覽器打開看
3. `kaeru.jsx`，現有的 React 原型

**這個 App 是什麼**

Kaeru，2026 年 11 月日本退稅新制（先付後退）的旅客小幫手。旅客把每張免稅收據集中管理，追蹤四段處理狀態、90 天期限、同店同日稅抜 5,000 円門檻，出境前在機場用「查驗進度」頁自己核對還剩哪幾張沒辦。介面是繁體中文加日文雙語。

**最重要的原則：只換視覺層，不要重寫邏輯。**

`kaeru.jsx` 裡的商業邏輯已經正確，包括 `netOf`、`daysLeft`、`groups`、`taxOf`、`stats`、i18n 字串 `T`、以及 `QA` / `TIPS` / `RULES` / `SIM` 幾組資料。這些照用。你要改的是 render 的部分：色票、字級、版面結構。

**實作順序**

1. 先把 `C` 色票換成 `README.md` 裡的表格，字體與字級規則統一
2. `HomeView` → `ListView` → `CheckView` → `FaqView` / `Scenario` → `SettingsView` → `EditSheet` / `DetailSheet`
3. 最後套 RWD（`README.md` 的 RWD 章節）

**有三個地方跟舊原型行為不同，不是單純換皮：**

**A. 查驗頁的用途改了。** 舊的叫「查驗模式」，做成給海關人員看的票券樣式。這是錯的，海關看的是機台判定和實體商品，不會看使用者的手機。新版叫「查驗進度」，是使用者在機場排隊時自己核對用的：頂端「還剩 3 張」大字加進度條，每筆下面一顆「辦完了」按鈕，按下去那張從清單消失、進度條前進。批次按鈕只在剩兩張以上時出現。中日並列的標籤（`税込 / 含稅`）全部拿掉，跟著介面語言走。

**B. 稅率欄位從兩顆變三顆。** 日本同一張收據常常同時有 8% 和 10%（食品 8%、酒類和其他商品 10%、外食內用 10%、外帶 8%），只能選一個稅率的話混合情況會算錯。新版是 `8%` `10%` `兩種都有`。前兩顆行為跟現在一樣點一下就結束，九成情況是單一稅率，不要為了少數情況拖慢主流程。點第三顆才展開兩格輸入（`8% 對象 含稅金額`、`10% 對象 含稅金額`），填完自動算稅額、自動帶入含稅總額。達標判定要用**稅抜合計**對 5,000 円門檻，不是含稅總額。細節看 `README.md` 的「6a. 稅率欄位」。

**C. 沒有底部分頁列。** 導覽全在標題列右側：`＋`（新增收據）、`▤`（收據清單捷徑）、`≡`（選單）。

**視覺上不能弄錯的三件事：**

1. **顏色有語意，不可混用。** 灰綠 `#93A392` = 已達標／已完成；灰赭 `#B08D74` = 警示（分「還救得回來」與「已失效」兩種語氣）；灰藍 `#77899A` = 進行中、還有下一步。線框標籤（`1px solid #E1DCD5`）= 純紀錄，不搶注意力。

2. **票券語彙只用在收據清單和收據卡。** 四方角、`1px solid #E1DCD5`、群組底線、虛線分隔，只有那裡用，因為那裡三種狀態要並排比較，框和底色在做區分工作。其他所有畫面都是無卡片，只有分隔線與留白。唯一例外是**空狀態的待填容器**（總覽未命名行程的卡、照片占位框）用 `1px dashed`，虛線代表「還沒填」，語意跟票券的實線框不同。

3. **收據卡三態必須能一眼分辨。** 這個 App 最容易出事的地方就是狀態長太像。看 `screenshots/12``14` 和 `README.md` 的三態對照表。失效狀態改變的是卡本身（底色填灰、金額劃線、進度點空心），不只是換標籤文字。

**其他**

- 所有數字用 `font-variant-numeric: tabular-nums`，金額用 600 字重，不要細體
- 字體 Noto Sans TC / JP，不要襯線體（中日混排會不一致）
- 圖示在 `icons/`，直接放進 `public/`，掛法在 `README.md`
- 資料只存本機，不要加任何後端或上傳
- 不要用 emoji

有任何規格上的疑問，先問我，不要自己猜。
