# Handoff: Kaeru 日本退稅小幫手 — 視覺方向 2a

## Overview

Kaeru 是 2026 年 11 月日本消費稅免稅新制（先付後退）的旅客小幫手 App。使用者把每張免稅收據集中管理，追蹤四段處理狀態、90 天期限、同店同日稅抜 5,000 円門檻，出境前在機場用「查驗進度」頁自己核對還剩哪幾張沒辦。

視覺方向已定案為 **2a**，設計稿 `Kaeru 產品畫面.dc.html` 只包含這個方向，全部畫面都要實作。（第一輪的 1a / 1b / 1c 已從設計稿移除。）

## About the Design Files

這個 bundle 裡的 HTML 檔案是 **設計參考稿**：用 HTML 畫出來的視覺與行為意圖，不是可以直接搬進產品的程式碼。

任務是把這些畫面 **在目標 codebase 既有的環境裡重做一次**（此專案已有可跑的 React 原型 `kaeru.jsx`，請沿用它的元件結構、state 與 `window.storage` 持久化方式，只換掉視覺層）。原型中的商業邏輯（`netOf`、`daysLeft`、`groups`、`taxOf`、`stats`、SIM 題庫、QA/TIPS/RULES 文案）已經正確，**不要重寫，只改 render**。

## Fidelity

**High-fidelity。** 顏色、字級、字重、間距、邊框都是最終值，請照數值實作。手機寬度基準 390px（iPhone 14/15 邏輯寬度），高度 844px。

### 形狀與間距

- 手機外框 `border-radius:30px`，`1px solid #E1DCD5`

## Navigation

**沒有底部分頁列。** 導覽全在標題列右側：`＋`（新增收據）、`▤`（收據清單捷徑，在收據頁時轉 `#77899A`）、1px 分隔、`≡`（選單：直接用行程切換彈跳面板，面板裡加上五個主畫面的列）。標題列底部 `1px solid #E1DCD5`，左側是 wordmark（`KAERU`，12.5px/600，`letter-spacing:0.28em`，`blueDeep`）＋青蛙標誌 26px＋行程名，或該頁標題（20px/700）。子頁面左上角一律寫「‹ 上一頁的名字」；手機返回鍵在主畫面先回總覽、在總覽才進離開流程（規則見 `CLAUDE_CODE_DELTA_返回與離開.md`）。

`▤`／`＋`／`≡` 是 placeholder 字元，實作請換成 24px grid、2px stroke 的圓角線性 icon（原型用 lucide：`Plus` / `Receipt` / `Menu` / `X` / `ChevronRight`）。

### 6a. 稅率欄位（新增收據內）

**為什麼改**：日本同一張收據常常同時有 8% 和 10%。食品是輕減稅率 8%，酒類和其他商品 10%，外食內用 10%、外帶 8%。只能選一個稅率時，混合情況算出來的稅額會錯。

**三題按鈕**：`8%` ｜ `10%` ｜ `兩種都有`，`flex: 1 / 1 / 1.5`、`gap:6px`、`padding:10px 0`、13px/600。選中 `#77899A` 底白字，未選 `#F4F2EF` 底＋`1px solid #E1DCD5`＋`sub` 文字。四方角。日文標籤：`8%` / `10%` / `両方あり`。

按鈕下方固定一行說明（11.5px/line-height 1.75、`sub`）：「以收據上的標示為準，有 ※ 記號的是 8%。」日文：「レシートの表示を優先。※ マークは 8% 対象。」

**單一稅率（`19-tax-single.png`）**：點 `8%` 或 `10%` 就結束，下方維持現有的「含稅金額」單一欄位＋稅額區塊。九成的情況是單一稅率，不要為了少數情況拖慢主流程。

**兩種都有（`20-tax-mixed.png`）**：點第三顆才展開。原本的單一「含稅金額」欄位 **消失**，換成 `1px solid #E1DCD5` 上邊後的兩格（列間 15px）：

- 左側 label：`8% 對象` 12.5/700 ink＋副標 `食品、外帶` 10.5px `sub`
- 左側 label：`10% 對象` 12.5/700 ink＋副標 `酒類、其他商品`
- 右側輸入：`flex:1; max-width:168px`、`text-align:right`、19/600 tabular、底線 `1px solid #E1DCD5`（focus 時 `#494640`）；placeholder 文字為「含稅金額」`sub` 色

**為什麼是輸入含稅對象金額而不是稅額**：日本收據下方本來就印成「8%対象 4,104円（内消費税 304円）」，欄位對得起來，眼睛不用在收據上跳來跳去。

兩格下方的 `#F4F2EF` 匯總區塊（padding 14px）：

1. 「含稅總金額」＋「自動帶入」11px `sub` 左，20/600 ink 右 — **使用者不用再填一次總額**
2. `1px solid #E1DCD5` 後兩行 11.5px `sub` tabular：`8% 對象 稅抜 ¥3,800` / `稅額 ¥304`；`10% 對象 稅抜 ¥8,000` / `稅額 ¥800`
3. `1px solid #E1DCD5` 後稅額合計列：左「稅額合計（可手動改）」＋「稅抜合計 ¥11,800」，右 22/600 blueDeep

計算：`tax8 = round(v8 / 1.08 * 0.08)`、`tax10 = round(v10 / 1.10 * 0.10)`，達標判定用**稅抜合計**（`v8/1.08 + v10/1.10`）對 5,000 円門檻，不是含稅總額。

**只填一格（`21-tax-mixed-partial.png`）**：匯總區塊的含稅總額改 `sub` 色（尚未完成），已填那行照常顯示，未填那行右側寫「還沒填」；下方一顆 clay 填色標籤 `10% 對象還沒填`＋一行 11.5px `sub` 提示「照收據上的兩行金額各填一格。這張只有 8% 的話，回上面選 8% 就好。」儲存按鈕不鎖，但儲存時若仍只填一格，自動降回該單一稅率模式。

**切換行為**：從混合切回單一時，兩格的值相加帶回單一「含稅金額」，兩格不清空（使用者切回來時還在）。單一模式下兩格完全不出現。展開動畫 180ms。

## RWD

單欄置中，不切兩欄、不加側邊導覽，導覽永遠在標題列。

### 容器

```css
.app {                        /* 內容欄 */
  width: 100%;
  max-width: 480px;
  margin-inline: auto;
  background: #FFFFFF;
  min-height: 100dvh;
}
body { background: #F2F0ED; } /* 欄外留白 */
```

- 內容欄從 320 長到 **480 就停住**，之後只有左右留白變多。桌機不需要另一套版面。
- ≥768 時欄的上下貼滿視窗（`min-height:100dvh`），左右邊界可加 `1px solid #E1DCD5`，不要圓角、不要陰影，不要做成漂浮卡片。
- 手機不要 `border-radius`（設計稿上的 30px 圓角只是手機外框示意，不是 UI）。

### 斷點

| 寬度 | 行為 |
|---|---|
| < 390 | **整體等比縮放**，版面不重排：`html { font-size: calc(16px * min(1, 100vw / 390)); }`，或在 `.app` 上 `transform: scale(100vw / 390)` + `transform-origin: top center`。字級、間距全部改用 `rem` 才會跟著縮 |
| 390–480 | 欄寬 = 視窗寬，內距 26px。基準設計尺寸 |
| 480–767 | 欄寬鎖 480，內距 26px，兩側留白 |
| ≥ 768 | 同上，欄不再變寬，留白吃掉其餘空間；標題列與底部按鈕都在欄內，不做 full-bleed |

### 隨寬度變的值（只有這些，其他一律不動）

| 屬性 | <390 | 390–480 | ≥480 |
|---|---|---|---|
| 左右內距 | 26px（隨縮放） | 26px | 30px |
| 主數字（倒數／還剩張數） | 48px 隨縮放 | 48px | 52px |
| 可退稅額 | 42px 隨縮放 | 42px | 46px |
| 內文 | 13px 隨縮放 | 13px | 13px（不放大） |
| 收據卡群組間距 | 18px | 18px | 22px |

字級只在主數字放大，內文與標籤不隨寬度變。

### 各畫面的注意事項

- **總覽**：四列數字是 label 左／值右的 `space-between`，寬度變化只影響中間空白。倒數的「2 天 14 小時」是一行，`white-space: nowrap`
- **收據清單**：群組表頭左右兩欄，右欄 `text-align:right` 且 `flex:none`；店名 `min-width:0` + `text-overflow:ellipsis`，長店名截斷而不是換行
- **查驗進度**：含稅／稅額 `gap:30px` 固定，不用 `flex:1` 撐開；1px 進度條寬度隨欄寬
- **FQA**：答案段落 `margin-right:24px` 保持右側呼吸，欄寬 480 時行長約 40 字，不再放寬
- **新增收據**：稅率 8%／10% 兩顆各 `flex:1`；三個開關列高度固定 44px 以上
- **詳情**：三欄摘要（稅率／稅抜金額／同店同日合計）在 <360 時允許換成兩行，其餘維持一行
- **情境模擬**：九段進度條用 `flex:1` 等分；選項卡寬度滿欄
- **行程切換**：底部面板固定在 **欄內**（`position:absolute` 相對 `.app`，不是 viewport），寬度跟著欄，≥768 時仍貼欄底，不改成置中 modal

### 其他

- `<meta name="viewport" content="width=device-width, initial-scale=1, viewport-fit=cover">`
- 安全區：標題列 `padding-top: max(14px, env(safe-area-inset-top))`；底部固定按鈕 `padding-bottom: max(22px, env(safe-area-inset-bottom))`
- 高度用 `dvh` 不用 `vh`（iOS Safari 網址列）
- 觸控目標最小 44×44，線框按鈕現為 `padding:9px` + 12.5px 字 ≈ 38px，實作時補到 44
- 橫向：手機橫放沿用同一單欄，不做橫式版面

## Interactions & Behavior

- Hover（桌機/平板）：線框按鈕底色 `rgba(73,70,64,0.04)`；實心 blue 按鈕壓深至 `#5C6D7C`
- Press：`transform:scale(0.98)`
- Transition：180–220ms `cubic-bezier(0.4,0,0.2,1)`；FAQ 展開 150ms
- 查驗進度：單筆「辦完了」→ 移除 + 進度條前進；批次按鈕僅剩 ≥2 張顯示
- 情境模擬：選項一經點選鎖定並展開回饋，金額 count-up 500ms
- 匯率：`open.er-api.com/v6/latest/JPY`，失敗顯示 `rateFail` 文案並允許手動輸入
- 資料只存本機（原型用 `window.storage`），照片先 `compressImage(maxSide 1000, quality .6)` 再存
- 期限：`daysLeft = 購買日 + 90 − 今天`；≤14 天用 clay，≤30 天用線框標籤，<0 顯示「已超過 90 天期限」
